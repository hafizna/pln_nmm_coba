jawab pertanyaan yang lebih penting.

Usulan pilot NMM: satu GI, dengan asset extract yang sudah structurally cleaned dan SLD GI yang relevan. Tujuannya mengukur apakah network model dapat dibentuk dengan sedikit human re-entry sebelum PLN mempertimbangkan scale-up.

PLN Network Model Management1
Kenapa NMM dibahas ulang

PoC sebelumnya membuktikan jalur teknis, tetapi belum menjawab biaya membangun dan memelihara model.

Yang sudah dibuktikan

  • CIM/XML dapat menjadi jalur interchange.
  • Model yang sudah dipersiapkan dapat diteruskan ke PowerFactory.
  • Hasil/state dapat dikembalikan.

Yang belum dibuktikan

  • Data existing PLN cukup untuk membentuk topologi aktual.
  • Engineer tidak perlu mengisi ulang data besar.
  • Model dapat dipelihara sebagai SSOT lintas unit.
  • Maintenance burden layak dibanding manfaatnya.
Technical path ≠ production feasibility2
Problem inti

Asset register dan SLD menjawab pertanyaan yang berbeda.

Asset data

Menjawab: aset apa yang ada, ID-nya apa, berada di location mana, manufacturer, tahun, NIA, TECHIDENTNO, lifecycle.

SLD

Menjawab: aset itu berfungsi sebagai apa secara elektrik, urutannya bagaimana, tersambung ke bus/node mana, dan relasi antar-bay.

NMM diperlukan di titik pertemuan keduanya: physical asset → functional equipment → electrical topology.

LOCATION/PARENT bukan electrical connectivity.3

Kenapa bukan per bay?

Perlu konteks busbar, coupler, transformer antar-voltage-level, dan consistency antar-bay.

Kenapa belum raw bulk?

Supaya MVP tidak berubah menjadi proyek ETL besar sebelum kita tahu apakah network reconstruction-nya sendiri feasible.

Bulk tetap ada di roadmap — sebagai staging + per-GI job splitter.4

Data request #2

Yang diminta: SLD GI yang sesuai/relevan dengan asset extract.

PREFERRED

Source

Approved/as-built/latest revision bila tersedia.

NEEDED

Content

Busbar, bay/circuit labels, PMT/PMS/ES, trafo/line, dan primary measurement equipment yang terbaca.

ACCEPTABLE

Format

Vector/original ideal; PDF atau image tetap dapat dipakai untuk pilot.

Kalau asset extract dan SLD berbeda revisi, perbedaannya justru menjadi temuan reconciliation yang perlu dilacak.

SLD adalah topology evidence, bukan sekadar gambar background.6
Yang sengaja belum diminta

Pilot tidak perlu menunggu semua data engineering lengkap.

Belum perlu

R/X/B semua line, transformer impedance, load P/Q.

Belum perlu

Relay setting, defense-scheme logic, real-time SCADA.

Belum perlu

CGMES transaction package atau cross-border use case.

Pertanyaan pertama hanya: bisakah topology yang benar dibangun dari data existing tanpa input manual berlebihan?

MVP berhenti di ASSET_READY → TOPOLOGY_READY → CIM_READY.7
Apa yang aplikasi lakukan

User tidak membangun ulang model; user hanya menyelesaikan ambiguity.

clean asset + SLD ↓ normalize & group candidate ↓ match asset ↔ SLD evidence ↓ AUTO_RESOLVED / REVIEW_REQUIRED / CONFLICT / UNRESOLVED ↓ review per bay ↓ Terminal + ConnectivityNode ↓ canonical GI graph ↓ CIM/XML + generated SLD + report
Manual XY hanya layout override, bukan input connectivity.8
Deliverable balik ke BPO

Dari satu paket data, pilot menghasilkan bukti feasibility yang bisa diukur.

Model

Asset-to-functional mapping, topology graph, generated SLD, CIM/XML.

Quality

Conflict, unresolved evidence, dangling check, provenance dan readiness.

Effort

Berapa banyak keputusan manusia yang benar-benar dibutuhkan untuk publish satu GI.

Output bukan hanya demo visual — ada measurement dan audit trail.9
Pilot KPI

Go/no-go harus berdasarkan reduction of manual work.

≥95%

asset rows masuk tanpa ketik ulang

≥80%

functional grouping auto/proposed

≥80%

topology relation berasal dari evidence

<20%

object memerlukan keputusan manusia

100%

assumption/conflict terlihat

0

dangling internal reference saat publish

Angka di atas adalah target diskusi pilot, bukan threshold kebijakan final.

Hasil buruk juga bernilai: berarti upstream data perlu diperbaiki sebelum scale.10

Security

Data tetap PLN-controlled dan model yang dipublish harus auditable.

Source

Immutable evidence, source hash/revision, read-only ingestion.

Access

RBAC/least privilege pada production; model scope dapat dibatasi.

Release

Draft → Reviewed → Published, dengan model version dan rollback.

NMM tidak membutuhkan data dipublikasi keluar PLN untuk membuktikan feasibility.

Security/provenance adalah bagian dari model lifecycle.12

Request to BPO

Yang dibutuhkan untuk memulai bukan rollout nasional.

1. Pilih satu GI

Representatif, data asset relatif lengkap, SLD tersedia, complexity tidak ekstrem.

2. Berikan dua evidence set

Cleaned asset extract + corresponding SLD/revision.

3. Nominate reviewer

Satu engineering contact untuk menjawab exception/ambiguity yang benar-benar tidak dapat diputuskan dari sumber.

4. Tentukan handling

Konfirmasi batas penggunaan internal, klasifikasi, dan penyimpanan prototype.

Dari satu GI ini kita bisa menentukan dengan data: apakah NMM layak diskalakan, perlu perbaikan upstream dulu, atau perlu di-scope ulang.

Minimum data request → measurable go/no-go evidence14
